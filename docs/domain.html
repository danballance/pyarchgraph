Package 01 / pyarchgraph.domain

Domain

Understands imports and decides what the collected information means.

10 modules55 classesWalkthrough + class index

Its role

The domain gives meaning to the information collected from a Python project. It knows what a source module, import fact, dependency, and finding represent, and the rules that connect them.

Describe the source

Keep identities, import statements, context, and evidence in a shared vocabulary.

Interpret relationships

Resolve imports, build views, and explain cycles or unresolved targets.

Protect meaning

Check evidence and decide whether the declared analysis scope is complete.

The application supplies collected observations and asks these rules to work on them. The domain performs no file access and imports no graph library. Its graph contracts let an adapter supply the graph operations.

Process flow

Follow the collected sources through domain rules to the final report. The application coordinates these steps; the arrows show the main data flow, rather than parallel execution or every method call. Request and root validation happen before the observations shown here.

The shared snapshot carries sources, import facts, selected dependencies, original resolver dependencies, and external or unresolved imports. Each registered view then receives its own cycle analysis and selected checks. Cycle counts are computed even when no checks are selected.

Coverage has its own rules. Collection and resolution diagnostics, layout observations, and referenced target boundaries determine completeness. The application calculates this after successful view evaluation and combines it with all view reports. A complete report can contain error findings.

Recoverable source failures continue as diagnostics alongside the available results. A registered view or check that raises or returns invalid output produces ExtensionError and stops the analysis without a report.

Follow an import

Imagine analysing the demo directory from its parent. Both files contain an ordinary, top-level import.

  1. Give the observations stable identities

    Discovery supplies two SourceModule values. Their IDs become source:demo/orders.py and source:demo/inventory.py. Once the application has aligned paths, FactCanonicalizer turns the two drafts into identified ImportFact values.

  2. Match each import to its target

    StaticImportResolver uses known bindings to connect orders to inventory, and back again. Each DependencyEdge keeps the fact ID and resolution kind explaining why that relationship exists.

  3. Choose the relationships for analysis

    ArchitectureDependencyPolicy removes redundant package-base evidence where a fact already identifies a probable child. These plain imports keep both edges. The application places selected dependencies, the original resolver output, sources, and facts in one AnalysisSnapshot.

  4. Build a view and explain its cycle

    A view turns the snapshot into a ViewGraph. CycleAnalyzer asks the graph contract for cyclic groups, interprets the supporting facts, and selects a witness: inventory → orders → inventory.

  5. Turn the observation into a finding

    CycleCheck returns a CheckResult containing an error-level CycleFinding. The application adds the check ID and includes it in the view report.

A fact records an imported item. Resolution explains its target; evidence keeps the link back to the original statement. These are separate steps so findings stay explainable.

Views and findings

The default composition includes source and package views for each of three import filters. Source views keep one node per file; package views group those sources after filtering.

Six perspectives on the same sources
Source viewPackage viewImports retained
structuralpackage-structuralAll explicit import statements.
non-typingpackage-non-typingEverything except recognised TYPE_CHECKING bodies.
module-bodypackage-module-bodyAlso omits imports inside functions or methods; class bodies outside functions remain.

PackageView wraps a source strategy. A module belongs to its immediate containing package; an initializer belongs to its own package. Nodes use package:<dotted-name> IDs with disjoint memberships. Parent packages do not duplicate child-package sources. Standalone modules and sources without reliable bindings remain individual source nodes, so the walkthrough's two standalone files retain their cycle in all six views.

An optional max_depth caps the package's dotted name: depth 1 groups acme.orders and acme.inventory under acme; depth 2 keeps them separate. Projection drops dependencies inside a node, merges original evidence between shared endpoints and retains isolated nodes. A package cycle may exist even if no individual source modules form a cycle.

Namespace package sources group without __init__.py. An import of only the namespace container has no source target, so it does not create a graph edge. GraphValidator verifies original evidence and disjoint source memberships for package views and extensions alike.

The snapshot's optional resolved_dependencies preserves resolver evidence removed by module-level dependency selection. Package projection restores exact-base evidence only for the same retained import fact whose probable-child evidence maps to the same target package. This retains certainty without adding an unrelated package relationship. Older snapshots without the extra collection remain supported.

A cycle finding describes one cyclic group and one witness. A group can contain several cycles. “Definite” means it contains a cycle supported by exact resolution; it does not predict a crash when Python executes the project.

UnresolvedImportCheck reports unresolved imports retained by the view, except unmodelled namespace bases. Extensions may return a RuleFinding for other observations. CheckResultValidator checks their shape, source references, and evidence.

Coverage is a separate decision. CoveragePolicy requires no error diagnostics and acknowledgement of every encountered boundary. A complete analysis can still contain error findings, as this two-file example does.
